# 4. Exact ROS 2 Interface

아래 Topic 이름, Message Type, 필드 의미, 단위, Publisher/Subscriber를 팀 공통 계약으로 사용한다.

## 4.1 Camera → Perception: RGB Image

```text
Publisher: camera_node
Subscriber: perception_node
```

## 4.2 Camera → Perception: Depth Image

```text
Topic: /camera/depth/image_raw
Type: sensor_msgs/msg/Image
Publisher: camera_node
Subscriber: perception_node
```

## 4.3 Perception → Control: Target

```text
Topic: /target
Type: realsense_tracker_interfaces/msg/Target
Publisher: perception_node
Subscriber: control_node
```

`ros2_ws/src/realsense_tracker_interfaces/msg/Target.msg`:

```text
std_msgs/Header header
bool detected
float32 center_x_px
float32 center_y_px
float32 error_x_norm
float32 error_y_norm
float32 area_ratio
float32 depth_m
```

| 필드 | 의미 | 단위/범위 |
|---|---|---|
| `header.stamp` | 인지 결과 생성 시각 | ROS time |
| `header.frame_id` | 기준 카메라 Frame | 프레임 식별 문자열 |
| `detected` | 목표 검출 여부 | `true` / `false` |
| `center_x_px`, `center_y_px` | 검출된 퍽 중심 좌표 | pixel |
| `error_x_norm`, `error_y_norm` | 화면 중심 대비 좌우·상하 오차 | `-1.0` ~ `+1.0` |
| `area_ratio` | 퍽 영역 / 전체 영상 영역 | `0.0` ~ `1.0` |
| `depth_m` | 퍽까지의 Depth 거리 | m |

오차 부호:

```text
error_x_norm: -1.0 = 화면 왼쪽, 0 = 중심, +1.0 = 화면 오른쪽
error_y_norm: -1.0 = 화면 위쪽, 0 = 중심, +1.0 = 화면 아래쪽
```

`detected == false`이면 제어는 나머지 수치 필드를 사용하지 않는다. 중심 좌표는 픽셀 단위이고, 실제 모터의 양·음 방향은 조립 방향에 따라 달라질 수 있으므로 설정으로 보정한다.

## 4.4 Control → OpenCR: Pan/Tilt Command

```text
Topic: /control/pan_tilt_cmd
Type: realsense_tracker_interfaces/msg/PanTiltCommand
Publisher: control_node
Subscriber: opencr_node
```

`ros2_ws/src/realsense_tracker_interfaces/msg/PanTiltCommand.msg`:

```text
std_msgs/Header header
bool stop
float32 pan_velocity_rad_s
float32 tilt_velocity_rad_s
```

| 필드 | 의미 | 단위 |
|---|---|---|
| `header.stamp` | 명령 생성 시각 | ROS time |
| `stop` | 안전 정지 명령 | `true` / `false` |
| `pan_velocity_rad_s` | Pan 축 목표 속도 | rad/s |
| `tilt_velocity_rad_s` | Tilt 축 목표 속도 | rad/s |

ROS 2 Interface는 `rad`, `rad/s`를 사용한다. Firmware가 다른 단위를 사용하면 `opencr_node` 또는 Serial 변환 계층에서 변환한다. `stop == true`일 때 두 목표 속도는 모두 `0.0`이어야 한다.

## 4.5 OpenCR → ROS 2: Motor State

```text
Topic: /motor/state
Type: sensor_msgs/msg/JointState
Publisher: opencr_node
Subscriber: control_node
Joint names: pan_joint, tilt_joint
```

`JointState`의 `position[]`은 rad, `velocity[]`는 rad/s이며, `effort[]`은 하드웨어가 제공하는 경우 사용한다. 각 배열 항목은 `name[]`의 같은 인덱스 Joint에 대응한다.

# 5. Perception → Control

```text
RGB + Depth
  → 파란색 퍽 탐지
  → 중심 좌표 / 정규화 오차 / 면적비 / Depth / 검출 여부
  → /target (realsense_tracker_interfaces/msg/Target)
```

미검출일 때도 계약된 Target 메시지를 발행하고 `detected=false`로 표현한다. `header.stamp`는 결과 시각, `header.frame_id`는 카메라 기준 Frame을 담는다.

---

# 6. Control → OpenCR

제어 담당은 화면 오차로부터 각 축의 속도 명령을 만든다.

```text
pan_cmd  = Kp_pan  × error_x_norm
tilt_cmd = Kp_tilt × error_y_norm
```

```text
/target → detected/timestamp 확인 → Pan/Tilt P 제어
        → 속도 제한 → 각도 제한 → 안전 정지 판단
        → /control/pan_tilt_cmd
```

---

# 7. OpenCR → ROS 2

OpenCR은 Pan/Tilt Dynamixel 상태를 `/motor/state` (`sensor_msgs/msg/JointState`)로 발행한다. `name[]`에는 `pan_joint`, `tilt_joint`를 사용한다. 제어는 실제 축 위치·속도와 각도 제한 상태를 확인한다.

# 9. ROS 2 Interface Dependency

Custom Message는 Node 패키지와 분리한 Interface 전용 패키지에서 관리한다.

```text
ros2_ws/src/
├── realsense_tracker/             # Python ROS 2 Nodes
└── realsense_tracker_interfaces/
    └── msg/
        ├── Target.msg
        └── PanTiltCommand.msg
```

Node 의존성:

```text
camera_node: sensor_msgs/msg/Image
perception_node: sensor_msgs/msg/Image, realsense_tracker_interfaces/msg/Target
control_node: Target, PanTiltCommand, sensor_msgs/msg/JointState
opencr_node: PanTiltCommand, sensor_msgs/msg/JointState
```

메인 패키지는 실제 사용에 맞춰 `rclpy`, `sensor_msgs`, `std_msgs`, `realsense_tracker_interfaces` 의존성을 선언한다.

# 11. Interface별 담당 — 제어

```text
SUBSCRIBE
/target       realsense_tracker_interfaces/msg/Target
/motor/state  sensor_msgs/msg/JointState

PUBLISH
/control/pan_tilt_cmd  realsense_tracker_interfaces/msg/PanTiltCommand
```

`error_x_norm`을 Pan, `error_y_norm`을 Tilt 축에 적용하고 P 제어 결과를 속도·각도 제한 후 발행한다. 모터 부호 보정과 제한 파라미터는 설정을 사용한다.

# 12. Interface별 담당 — 통합


통합 담당은 Topic/Message 일치, 필드 의미·단위·부호, timestamp, Launch 구성, Serial 변환 및 Firmware watchdog 동작을 확인한다.

# 13. 검증·문서화

## 13.1 Interface 검증

```bash

ros2 topic type /camera/color/image_raw
ros2 topic type /camera/depth/image_raw

```

Topic Type, Publisher/Subscriber, 필드, 단위, timestamp, Joint 이름을 확인한다.

## 13.2 안전 정지 계약

### 목표 미검출

```text
/target.detected == false
→ control_node: stop=true, pan_velocity_rad_s=0, tilt_velocity_rad_s=0
```

### `/target` 입력 중단

설정된 `target_timeout` 동안 유효 Target이 없으면 `control_node`가 `stop=true`와 두 축의 0 속도를 발행한다.

### Control ↔ OpenCR 통신 중단

설정된 `command_timeout` 동안 OpenCR이 새 명령을 받지 못하면 OpenCR Firmware watchdog이 Pan/Tilt를 정지한다. ROS 2가 중단되어 정지 메시지를 보낼 수 없는 상황도 Firmware가 처리해야 한다.

### 복구

정지 상태에서 유효한 Target을 3회 연속 수신한 뒤 추적을 재개한다. 파라미터는 `recovery_valid_count: 3`이다.

## 13.3 필수 시험

1. 정상 추적 30초
2. 약 2초 가림 × 5회, 미검출 정지와 복구 확인
3. `/target` 입력 중단 및 `target_timeout` 정지
4. `/control/pan_tilt_cmd` 통신 중단 및 Firmware watchdog 정지
5. 최소 2개 `Kp` 설정 비교

## 13.4 성능 지표

| 지표 | 의미 |
|---|---|
| FPS | 인지 처리 속도 |
| Detection Rate | 목표가 보이는 프레임 중 정상 검출 비율 |
| Background False Detection | 목표가 없는 프레임에서의 오검출 |
| Horizontal RMSE | 수평 중심 오차의 RMS |
| Recovery Success | 가림 후 기준 시간 내 추적 복구 여부 |
| Recovery Time | 목표 재등장 후 정상 추적 복귀까지 걸린 시간 |

# 14. Interface 변경 규칙

확정 계약:

```text

/control/pan_tilt_cmd      realsense_tracker_interfaces/msg/PanTiltCommand
/motor/state               sensor_msgs/msg/JointState
```

Topic, Message Type, 필드 의미, 단위, 부호는 개인이 임의 변경하지 않는다. 변경 제안은 인지·제어·통합 협의와 검증 영향 확인 후 모든 Node, 문서, 시험 항목에 함께 반영한다.
